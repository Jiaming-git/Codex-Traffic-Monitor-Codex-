# Codex 流量后台监控

使用系统自带 Windows PowerShell 5.1，不依赖 Codex、Node.js 或 Python，不下载任何依赖。

## 使用

双击 `安装并启动.cmd` 即设置当前用户登录 Windows 后自动启动，并创建每分钟检查存活的当前用户计划任务。登录启动项为 `CodexTrafficMonitor.lnk`，不是管理员服务，注销或关机时退出。

- `查看状态.cmd`：查看最后采样时间、代理是否可用、Codex 归属端口数及日累计。
- `启动监控.cmd`、`停止监控.cmd`：手动开始或停止。停止不会取消下次登录启动。
- `卸载自启动.cmd`：停止监控并移除自己的登录启动项，保留脚本及历史记录。
- `测试告警.cmd`：显示 15 秒自检弹窗，不访问外网。

## 默认告警

每 2 秒读取本机 Clash 命名管道 `GET /connections`；每 10 秒通过 netstat 核对 ChatGPT/Codex 进程端口并增量读取当天应用日志。

| 条件 | 行为 |
| --- | --- |
| Codex 已观测 VPN 上传＋下载，5 分钟超过 200 MB | 本机弹窗和告警日志 |
| 1 小时超过 500 MB，或一天超过 2000 MB | 本机弹窗和告警日志 |
| 运行时 `outcome=failed` 且 `failureStage=activate_runtime` | 本机弹窗，提示检查重复下载 |
| 代理接口连续不可用，启动超过 2 分钟 | 提醒流量监测不可用，日志监测继续 |

流量告警首次越线时提醒；持续超标不会每15分钟重报。只有上次告警后又新增一个对应阈值的流量，或窗口下降到阈值90%以下后重新越线，才可再次提醒，且间隔至少15分钟。告警状态跨重启保存；升级时迁移已有告警，不把旧流量重复算作新事件。弹窗20秒后自动关闭。阈值是可调整的起始值，并非 Codex 正常用量标准。建议在 `config.local.json` 覆盖所需设置，修改后停止再启动监控。

只提醒，不结束其他进程、不关闭连接、不更改代理、Codex 设置或数据库。更新故障仍须另行修复；监控不能自动修复运行时更新，也不能保证阻止超额。

## 流量、资源与隐私

- 不调用模型，不打开浏览器，不向外部服务器发请求。命名管道数据仅在本机传输，不使用 VPN 套餐流量。
- 仍会使用少量 CPU、内存和磁盘，以及让 Clash 多处理本机只读查询；并非零资源占用。每 10 秒的 netstat 查询是只读的。
- 认证值从用户 Clash 配置读入内存，不写入状态、告警或日志。
- 运行数据在 `%LOCALAPPDATA%\CodexTrafficMonitor`，避开百度同步盘；日志保留 14 天。源码改动可能触发百度同步，这是同步软件自身行为。
- 记录每 15 秒采样汇总和告警，不保存聊天正文、账号令牌或完整网络请求内容。

## 统计边界

使用连接唯一 ID 计算上传＋下载增量，排除 DIRECT/REJECT 链。通过当前系统端口或代理提供的进程字段归属 Codex；无法归属的 OpenAI 域名不会硬算作 Codex（浏览器也可能访问同域名）。首次启动的已有连接只建立基线，不补记整段历史。

短于采样间隔的连接、关闭前最后一段传输或端口映射未捕获的连接可能漏计；所以“低于阈值”不能证明没有异常，数据也不是 VPN 账单。代理累计归零不会当成负流量。日累计同一天重启保留；未运行期间不补算，5 分钟/小时窗口重启时从本地汇总恢复，边界约有一个15秒汇总间隔的误差。

日志检测只提示监控启动前 5 分钟以来的激活失败，避免历史错误反复报警。计划任务 `CodexTrafficMonitor-Recovery` 每分钟用 `wscript.exe` 检查本监控是否退出，必要时隐藏启动 PowerShell 监控；正常检查不弹出控制台，停止标记存在时不启动。它不会结束其他程序或发起外网请求，每次检查使用少量本机资源。进程仍存在但状态长期未更新时需要另行检查。异常写入 `fatal-errors.jsonl`，外部强制结束不一定能记录原因。代理未启动不等于监控已失效退出。

## 迁移

支持 Windows 10/11、系统 Windows PowerShell 5.1、Windows Script Host 和当前用户计划任务。流量统计需要本机运行 Clash Verge Rev / Mihomo，并提供 `GET /connections` 命名管道接口。其他 VPN 客户端不能直接使用本工具统计。组织策略若禁用脚本宿主或计划任务，需先由管理员允许对应功能。

1. 在新电脑克隆仓库或下载并解压源码到固定目录，可以包含中文和空格。
2. 安装并启动 Clash Verge Rev 和 Codex。默认使用当前用户的 Clash 配置与 Codex 日志目录，不携带旧电脑认证信息。
3. 默认配置在 `config.json`。如需不同管道名、Clash 配置或日志目录，新建 `config.local.json`，只填写需要覆盖的键。例如：

   ```json
   {
     "hourMB": 500,
     "pipeName": "verge-mihomo"
   }
   ```

   `clashConfig`、`codexLogRoot` 留空会自动解析本机目录；自定义时填写目标电脑上的绝对路径。配置优先级为本地覆盖高于默认文件，`pipeName` 仅支持本机管道。不要把代理密钥写入配置文件。
4. 双击 `安装并启动.cmd`，创建或更新该电脑当前用户的启动项与存活检查任务。
5. 运行 `查看状态.cmd` 检查 `proxy` 是否为 `ok`、`updated` 是否刷新；需要时运行 `测试告警.cmd` 验证通知。

移动同一台电脑上的目录前先停止监控，再在新位置运行安装入口。每台电脑分别安装；源码可同步，`%LOCALAPPDATA%\CodexTrafficMonitor` 内的 PID、状态、告警状态和统计应留在原电脑。迁移不复制启动快捷方式或计划任务，安装脚本会按新路径重建。

## Git 管理与自检

仓库包含脚本、共享默认配置和说明；`.gitignore` 排除 `config.local.json`、`deployment-check.json`、日志、状态、备份和临时文件。当前电脑临时添加的域名拦截规则不在本仓库中，安装本工具不会设置代理规则。

在项目目录运行以下命令，可在临时中文含空格目录验证迁移、核心计数与告警逻辑。不安装启动项，不访问外网：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-Portability.ps1
```

这项自检不能替代新电脑上真实的代理接口、计划任务权限和弹窗检查。

接口参考：https://wiki.metacubex.one/api/
